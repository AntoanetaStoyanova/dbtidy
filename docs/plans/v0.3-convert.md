# Plan — v0.3 : `convert`, du SQL legacy aux modèles dbt en couches

*Rédigé le : 9 octobre 2026*
*Référence : [v0.3-convert.md](../specs/v0.3-convert.md)*

## Objectif

Ajouter `dbtidy convert`, qui découpe une requête Oracle legacy en `sources.yml`, staging, intermediate et mart conformes aux conventions. Les modèles sont modernisés, vérifiés par `check`, puis validés sur Oracle Free.

## Prérequis

- v0.2 commitée sur `develop` (publication PyPI non bloquante).
- Pour l'étape 10 : Docker installé, et accord pour `uv add --group oracle dbt-oracle`.

## Étape 1 — Spike : découpage de 3 requêtes

- [ ] `docs/spikes/convert_split.py`, script jetable sans tests, sur 3 requêtes :
  - jointure `(+)`, `NVL` et `GROUP BY` ;
  - CTE et `DECODE` ;
  - fonction analytique et `CASE`.
- [ ] Vérifier avec sqlglot :
  - extraction des tables et des colonnes utilisées par table (alias résolus), avec une auto-jointure ;
  - détection d'une colonne sans préfixe dans une jointure et de `*` ;
  - `sqlglot.optimizer.eliminate_join_marks` pour `(+)` ;
  - réécriture de `NVL` et `DECODE` ;
  - rendu `pretty` stable et relu sans erreur ;
  - détection de `CONNECT BY`, `UNION` et des sous-requêtes corrélées ;
  - réécriture du top N imbriqué `(SELECT … ORDER BY) WHERE ROWNUM <= n` en `FETCH FIRST`, et détection de `ROWNUM` au même niveau que l'`ORDER BY` ;
  - séparation d'un agrégat de l'expression qu'il contient (`SUM(NVL(x, 0))`), et repérage de ce qui porte sur un agrégat (`RANK() OVER (ORDER BY SUM(x))`).
- [ ] Afficher les fichiers que `convert` produirait pour chaque requête.
- [ ] Vérifier chaque ligne du tableau « Règles de découpage » sur les 3 requêtes.
- [ ] Reporter les conclusions dans la spec : trancher les décisions *(à confirmer)*, ajuster le périmètre et les étapes suivantes du plan si besoin.

## Étape 3 — Analyse de la requête

- [ ] `src/dbtidy/bin/convert/__init__.py` et `src/dbtidy/bin/convert/analyze.py` :
  - `ConvertError(Exception)` ;
  - dataclasses `SourceTable(schema, table, alias, columns)` et `Analysis(sources, ctes, has_logic, has_aggregation, unsupported)` ;
  - `analyze(sql: str, config: Config) -> Analysis`.
- [ ] Refus (`ConvertError`) :
  - entrée qui n'est pas un `SELECT` unique ;
  - table sans schéma ;
  - schéma absent de `convert.sources`, avec la liste des schémas à ajouter ;
  - colonne sans préfixe dans un `SELECT` à plusieurs tables, `*` ou `t.*`, avec la liste à corriger ;
  - sous-requête du `FROM` sans alias.
- [ ] Repérer :
  - les colonnes utilisées par table (y compris dans `WHERE`, `ON`, `GROUP BY`, `ORDER BY` et les sous-requêtes non corrélées), une table lue plusieurs fois étant fusionnée ;
  - les CTE et les sous-requêtes du `FROM` ;
  - pour chaque `SELECT` (requête principale, CTE, sous-requête), les éléments de logique (jointure, `WHERE`, alias, `CASE`, calcul, fonction, `OVER`), les éléments de changement de grain (`GROUP BY`, `HAVING`, `DISTINCT`, `ORDER BY`) et ce qui porte sur un agrégat ; la couche découle de la position, selon les « Règles de découpage » de la spec ;
  - le motif top N imbriqué, détecté ici seulement (`modernize` le réécrit).
- [ ] `unsupported` : liste `(construction, ligne, raison)` pour `CONNECT BY`, `UNION`/`INTERSECT`/`MINUS`, les sous-requêtes corrélées et `ROWNUM` hors top N.
- [ ] `@beartype` et docstrings NumPy.
- [ ] Tests (`tests/test_convert_analyze.py`) :
  - une ou deux tables ;
  - auto-jointure ;
  - alias ;
  - colonnes dans chaque clause ;
  - CTE ;
  - chaque construction non supportée ;
  - chaque refus.

## Étape 4 — Modernisation

- [ ] `src/dbtidy/bin/convert/modernize.py` : `modernize(tree: exp.Expr) -> exp.Expr` réécrit :
  - `(+)` → `LEFT JOIN ... ON` ;
  - `NVL` → `COALESCE` ;
  - `DECODE` → `CASE` ;
  - top N imbriqué marqué par `analyze` → `FETCH FIRST n ROWS ONLY`.

  Elle retire aussi l'`ORDER BY` seul d'une CTE ou d'une sous-requête et laisse une note. Elle ne modifie pas l'arbre reçu.
- [ ] Tests (`tests/test_convert_modernize.py`) :
  - chaque réécriture ;
  - `(+)` sur plusieurs colonnes ;
  - `DECODE` avec et sans valeur par défaut ;
  - top N imbriqué, et `ROWNUM` au même niveau laissé intact ;
  - `ORDER BY` retiré d'une CTE et conservé dans la requête principale ;
  - le résultat ne déclenche plus ORA001, ORA002 ni ORA003.

## Étape 5 — Génération des sources et du staging

- [ ] `src/dbtidy/bin/convert/generate.py` :
  - dataclass `GeneratedFile(path: Path, content: str, layer: Layer)` ;
  - `sources_yml(analysis, config) -> GeneratedFile` ;
  - `staging_models(analysis, config) -> list[GeneratedFile]`.
- [ ] Staging : `<staging>/<source>/stg_<source>__<table>.sql`, `select` des colonnes utilisées depuis `{{ source('<source>', '<table>') }}`, colonnes en `columns_case` (minuscules par défaut).
- [ ] Sources : un `<staging>/<source>/_<source>__sources.yml` par source.
- [ ] Préfixes tirés de `config.layers` ; `ConvertError` si un nom de modèle dépasse `oracle.max_identifier_length`.
- [ ] Rendu sqlglot `pretty`, décidé à l'étape 1.
- [ ] Tests (`tests/test_convert_generate.py`) :
  - contenu exact d'un `_<source>__sources.yml` et d'un staging ;
  - chemins et préfixes issus de `config.layers` ;
  - nom trop long → `ConvertError` ;
  - chaque staging relu par sqlglot et sans erreur `check`.

## Étape 6 — Génération de l'intermediate et du mart

- [ ] `generate.py` :
  - `intermediate_models(analysis, tree, config, renames) -> list[GeneratedFile]` : un `int_<cte>` par CTE ou sous-requête du `FROM`, avec son `GROUP BY` éventuel, plus `int_<nom>` si la requête principale a des éléments de logique. `renames: dict[str, str]` est appliqué aux noms de CTE et d'alias, avec `ConvertError` si un nom est inconnu ou invalide ;
  - `mart_model(analysis, tree, name, config) -> GeneratedFile` : `GROUP BY`, `HAVING`, `DISTINCT`, `ORDER BY`, ce qui porte sur un agrégat et `SELECT` final de la requête principale. Il lit directement le staging ou le `int_` d'une CTE quand il n'y a pas d'intermediate principal ;
  - `ConvertError` si deux modèles générés portent le même nom (message qui suggère `--rename`) ou si `name` n'a pas de préfixe mart.
- [ ] Remplacer les tables par `{{ ref('stg_...') }}` et les CTE par `{{ ref('int_...') }}`, après `modernize`.
- [ ] Tests :
  - un test par ligne du tableau « Règles de découpage » sans TODO (couche du modèle produit) ;
  - jointure et `GROUP BY` → `int_` et `fct_` ;
  - `GROUP BY` dans une CTE → dans `int_<cte>`, pas dans le mart ;
  - requête sans élément de logique → pas de `int_`, le mart lit le staging ;
  - `SUM(x) AS total` et `RANK() OVER (ORDER BY SUM(x))` → mart ;
  - sous-requête non corrélée dans le `WHERE` → dans l'`int_`, tables en `ref()` ;
  - staging sans `WHERE`, sans alias ni expression ;
  - CTE → `int_<cte>` référencé ;
  - fonction analytique conservée ;
  - `--rename` et collision de noms.

## Étape 7 — Séparation des agrégats, TODO et assemblage

- [ ] `generate.py` : séparation d'un agrégat de son expression interne ; l'expression va dans l'intermediate sous un alias, l'agrégat avec le calcul et l'alias qui l'entourent dans le mart.
- [ ] Constructions non supportées : fragment recopié dans le modèle, avec un en-tête `-- TODO` qui donne la raison et la ligne d'origine.
- [ ] `convert_query(sql, name, config, renames) -> list[GeneratedFile]`, qui assemble les étapes 3 à 7.
- [ ] Tests :

  - `CONNECT BY`, `UNION`, sous-requête corrélée, `ROWNUM` au même niveau que l'`ORDER BY` → `-- TODO` ;
  - cas limites de la spec ;
  - tous les modèles générés relus par sqlglot, et sans erreur `check` hors modèles `-- TODO`.

## Étape 8 — Commande `convert`

- [ ] `src/dbtidy/bin/convert/write.py` : `write_models(files, force, dry_run) -> WriteReport`.
  - Un staging existant est réutilisé s'il expose les colonnes requises ; sinon `ConvertError` avec les colonnes manquantes.
  - Un `int_` ou un `fct_` existant lève `ConvertError` sans `force`.
  - Un `_<source>__sources.yml` existant est complété des tables manquantes, avec un avertissement (commentaires perdus).
  - `dry_run` n'écrit rien.
- [ ] `__main__.py` : sous-commande `convert QUERY [--name] [--rename ANCIEN=NOUVEAU ...] [--config] [--force] [--dry-run]`. Un conflit de fichier suggère `--rename` dans le message.
  - Affiche les fichiers écrits ou réutilisés, les TODO, puis le rapport de `check` sur les modèles générés.
  - Codes de sortie : 0, 1 ou 2, selon la spec.
- [ ] Tests (`tests/test_convert_cli.py`, avec `tmp_path`) :
  - cas nominal de bout en bout ;
  - `--name` ;
  - `--rename` (fichier et `ref()` renommés, nom inconnu ou invalide → exit 2) ;
  - nom déduit du fichier ;
