# Plan — v0.2 : conventions en YAML et publication PyPI

*Rédigé le : 7 octobre 2026*
*Référence : [v0.2-config-pypi.md](../specs/v0.2-config-pypi.md)*

## Objectif

Remplacer les conventions codées en dur par un `dbtidy.yml` validé, introduire la sévérité, ajouter les règles ORA002-005 et NAM001-002, puis publier `0.2.0` sur PyPI.

## Prérequis

- v0.1 commitée sur `develop`.
- Accord pour `uv add pydantic pyyaml` et `uv add --dev types-PyYAML`.
- Pour l'étape 8 :
  - remote `origin` corrigé ;
  - compte PyPI avec un *trusted publisher* configuré ;
  - accord explicite pour pousser et taguer.

## Étape 1 — Modèle de configuration

- [x] `uv add pydantic pyyaml` et `uv add --dev types-PyYAML`, après accord.
- [x] `src/dbtidy/config/__init__.py` :
  - `Severity` (`StrEnum` : `error`, `warning`, `off`) ;
  - `LayerConfig(path, prefixes)` et `Config(layers, columns_case, oracle, rules)` en pydantic avec `extra="forbid"`, dont les valeurs par défaut reproduisent la v0.1 ;
  - `KNOWN_RULES` et `DEFAULT_SEVERITY` ;
  - validateur qui rejette un code de règle inconnu.
- [x] `ConfigError(Exception)` ; `load_config(path: Path | None) -> Config` lit le fichier, ou `dbtidy.yml` du répertoire courant, sinon renvoie les valeurs par défaut. Elle résout les chemins des couches par rapport au dossier du fichier et transforme les erreurs YAML et pydantic en `ConfigError` lisible (clé fautive et raison).
- [x] `@beartype` et docstrings Google, avec un doctest sur `Config()`.
- [x] Tests (`tests/test_config.py`) :
  - valeurs par défaut ;
  - fichier complet ;
  - fichier partiel fusionné avec les valeurs par défaut ;
  - clé inconnue, sévérité inconnue, code inconnu et YAML mal formé → `ConfigError` ;
  - fichier absent → valeurs par défaut.

## Étape 5 — Règles Oracle ORA002 à ORA005

- [x] Vérifier comment sqlglot 30 représente `NVL`, `DECODE` et `= ''` en dialecte Oracle (nœud et args), puis noter le résultat dans le journal.
- [x] `rules.py` :
  - `ora002_nvl` : `NVL` → `COALESCE` ;
  - `ora003_decode` : `DECODE` → `CASE` ;
  - `ora004_empty_string` : `=`, `<>` ou `!=` contre `''`, en suggérant `IS NULL` ou `IS NOT NULL` ;
  - `ora005_identifier_length` : alias, CTE et colonnes plus longs que `config.oracle.max_identifier_length`, en excluant les noms de `model.mapping`.
- [x] Ajout à `RULES`, `KNOWN_RULES` et `DEFAULT_SEVERITY`.
- [x] Tests :
  - un cas conforme et un cas en violation par règle ;
  - ORA005 avec la limite 30 puis 128 ;
  - un nom factice long n'est pas signalé ;
  - `tests/test_jaffle_shop.py` est mis à jour avec les nouveaux warnings.

## Étape 6 — Règles de nommage NAM001 et NAM002

- [x] `rules.py` :
  - `nam001_prefix_matches_folder` : un fichier situé sous le `path` d'une couche, mais dont le préfixe n'appartient pas à cette couche (ou à aucune), est signalé ligne 1, avec le préfixe attendu ;
  - `nam002_column_case` : les alias du `SELECT` le plus externe ne respectent pas `columns_case` (`lower` ou `upper`). La règle est inactive si `columns_case` est nul.
- [x] Tests :
  - `models/staging/int_x.sql` → NAM001 ;
  - `models/staging/stg_x.sql` → aucune violation ;
  - un fichier hors de tout dossier de couche → aucune violation ;
  - NAM002 avec `lower` et `upper` ;
  - NAM002 désactivée par défaut.
